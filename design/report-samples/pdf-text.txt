 05 / Sources and provenance
 Source excerpts are embedded so the evidence remains readable offline. Every source below was authored
 solely for this sample.

 SRC-REQ · Harbor service request rules
 Version 2.4 · Synthetic requirements authored for this design sample

 4.1 Requesters must not approve their own requests, including via direct routes. Denied attempts create an
 audit event. 4.3 Every approval stores the actor, timestamp and exact request revision. 4.4 Auditors can
 inspect but cannot edit or approve. 4.7 Rejection requires a non-empty explanation and must retain the form
 on validation failure. 4.8 Authorized attachment downloads preserve the original filename and content.


 SRC-API · Submission and confirmation contract
 Version 1.7 · Synthetic API contract authored for this design sample

 2.3 A timeout after server acceptance leaves confirmation pending until a status lookup resolves it; the UI
 must not claim success or failure prematurely. 2.4 Repeating a payload with its accepted idempotency key
 returns the original request identifier and creates no duplicate.


 SRC-CAL · Working-day scheduling policy
 Version 1.1 · Synthetic operations policy authored for this design sample

 3.2 Requests scheduled on a non-working day move to the next working day in the configured, versioned
 calendar. The chosen date is shown before confirmation.
